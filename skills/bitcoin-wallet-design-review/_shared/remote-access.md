# Running this skill without repo access

The skill is written for an agent with the repository checked out locally — Claude Code or equivalent. That agent reads screenshots and shared files straight off disk, and none of what follows applies to it.

This file is for the other case: an agent that reached the skill over HTTP and has only a fetch tool. That path is **not currently supported** — see the hard blocker at the bottom — but the routing details are recorded here because they were expensive to work out and remain accurate.

## The blocker

Anthropic's `web_fetch` supports **text, HTML, and PDF only**. Fetching a PNG or JPEG returns `unsupported_content_type`. This is a property of the tool, not of the host, the URL form, or the phrasing of the request:

- `raw.githubusercontent.com/.../01-onboarding-1st-screen.png` → refused
- `bitcoin-ui-gallery.netlify.app/screens/.../01-onboarding-1st-screen.png` → refused
- `github.com/GBKS/bitcoin-ui-gallery/raw/main/<path>` → 302-redirects to `raw.githubusercontent.com`, so it is the same host and fails identically. Image bytes are never served from `github.com` itself.

Since the Gallery's JSON records only a filename and a tag per screen — no description of screen content — an agent that cannot see the images has nothing to review. It must emit the preflight-failure block from `SKILL.md` and stop.

**The known way around this, untested:** bundle a flow's screenshots into a PDF and fetch that instead. Claude's PDF handling converts each page to an image and analyzes it visually, so a PDF is the one container that carries pixels through a text-only fetch. Limits are 32 MB per request and 100 pages for visual analysis; the largest flow in the Gallery is 20 screens at 1.5 MB, so size is not a constraint. Generate one page per screenshot at native dimensions — downscaling to A4 risks making the fine print unreadable.

## How the request is phrased

Three things caused fabricated reviews in practice, all worth avoiding if this path is revived:

- **Anchoring on the Netlify copy of `SKILL.md`.** Whichever host is named becomes the anchor for everything after it, and the agent invents sibling URLs there rather than using the table above.
- **Also handing over the wallet's gallery page** (e.g. `.../phoenix`). It's a rendered HTML page carrying screen titles and tags — enough to *look* like a data source while carrying no screen content. Its presence lets an agent that can't see the screenshots keep going instead of stopping, padding titles out with half-remembered knowledge of the app.
- **Naming the review mode up front.** It signals that target resolution is already settled, and the preflight above it gets skimmed along with it.
